# الأمان في docxi: الإبلاغ عن المشكلات والتعامل مع المدخلات غير الموثوقة

تشرح هذه الصفحة كيفية الإبلاغ عن مشكلة أمنية، والنقاط الأمنية التي ينبغي معرفتها عندما يمرر تطبيقك مدخلات المستخدمين إلى docxi.

## <a id="reporting-a-vulnerability"></a>الإبلاغ عن ثغرة

يُرجى عدم الإبلاغ عن المشكلات الأمنية في البلاغات (issues) العامة، بل أرسلها بالبريد الإلكتروني إلى عناوين الصيانة المذكورة في [<span dir="ltr">`docxi.gemspec`</span>](https://github.com/hammad417/docxi/blob/master/docxi.gemspec). اذكر إصدار docxi وطريقة مختصرة لإعادة إنتاج المشكلة.

## <a id="upgrade-from-00x"></a>الترقية من 0.0.x

يمرر docxi 0.0.x سلاسل مسارات الصور إلى <span dir="ltr">`Kernel#open`</span>. وتنفّذ <span dir="ltr">`Kernel#open`</span> أي سلسلة تبدأ بالرمز <span dir="ltr">`|`</span> كأمر shell، لذا فمن يتحكم في مسار صورة يستطيع تشغيل أوامر على خادمك. يفتح الإصدار 0.1.0 الملفات باستخدام <span dir="ltr">`File.open`</span> وينزّل عناوين URL باستخدام <span dir="ltr">`URI#open`</span>، ولا ينفّذ أي منهما أوامر.

## <a id="untrusted-input"></a>المدخلات غير الموثوقة

**تمرير النص آمن.** يُكتب النص ومحتوى الجداول والسلاسل الأخرى كنص XML أو كقيم سمات تُهرِّبها nokogiri. لا يمكن لمدخلات المستخدمين إضافة عناصر إلى المستند.

**مصادر الصور تحتاج إلى حذر.** تقبل <span dir="ltr">`add_media`</span>:

| المصدر | ما تفعله docxi |
|---|---|
| كائن IO فتحته بنفسك | تقرؤه |
| مسار ملف | تقرأ ذلك الملف من قرص خادمك |
| عنوان URL من نوع <span dir="ltr">`http`</span> أو <span dir="ltr">`https`</span> أو <span dir="ltr">`ftp`</span> | تنزّله من خادمك |

إذا كان المستخدم يستطيع اختيار المسار، فقد يحصل على أي ملف قابل للقراءة على خادمك، مثل ملفات الإعدادات أو المفاتيح، مُضمَّنًا في المستند. وإذا كان يستطيع اختيار عنوان URL، فسيطلبه خادمك، وقد يصل ذلك إلى عناوين داخلية (تزوير الطلبات من جانب الخادم، SSRF). مرّر كائن IO فتحته بنفسك، أو اسمح فقط بمسارات ومضيفين معروفين.

**الارتباطات التشعبية** تشير إلى أي مكان يحدده عنوان URL. تحقق من عناوين URL التي يقدمها المستخدمون قبل تمريرها إلى <span dir="ltr">`add_hyperlink`</span>.

## <a id="how-releases-are-protected"></a>كيف تُحمى الإصدارات

- تُنشر الإصدارات من GitHub Actions باستخدام النشر الموثوق (trusted publishing) في RubyGems، لذا لا يُخزَّن أي مفتاح API في المستودع.
- تضبط البيانات الوصفية للحزمة الخيار <span dir="ltr">`rubygems_mfa_required`</span>، لذا تتطلب عمليات الدفع التي تستخدم مفتاح API شخصيًا المصادقة متعددة العوامل.
