# docxi mit Rails, Rack und Hintergrundjobs verwenden

docxi hat keine Plugins und keine eingebauten Integrationen. Es ist reines Ruby, das ein `StringIO` zurückgibt, und funktioniert daher überall, wo Sie einen String senden oder speichern können. Diese Seite zeigt die üblichen Wege, es einzubinden. Das Rails-Controller-Muster ist dasselbe wie in der README, und die Testsuite läuft mit geladenem Rails 5.2 bis 8.1.

## <a id="rails-controller-send-the-file-to-the-browser"></a>Rails-Controller: die Datei an den Browser senden

```ruby
class ReportsController < ApplicationController
  def show
    word = Docxi::Document.new
    word.document.p { |p| p.text "Report for #{Date.today}" }

    send_data word.render.string,
              filename: "report.docx",
              type: "application/vnd.openxmlformats-officedocument.wordprocessingml.document"
  end
end
```

`send_data` setzt `Content-Disposition: attachment`, sodass der Browser die Datei herunterlädt. Mit Bundler wird docxi automatisch aus dem Gemfile geladen.

## <a id="rails-background-job-build-the-file-outside-the-request"></a>Rails-Hintergrundjob: die Datei außerhalb des Requests erzeugen

Große Dokumente oder Dokumente, die auf langsamen Abfragen beruhen, entstehen besser in einem Job:

```ruby
class MonthlyReportJob < ApplicationJob
  queue_as :default

  def perform(path)
    word = Docxi::Document.new
    word.document.p { |p| p.text "Monthly report", bold: true, size: 16 }

    File.binwrite(path, word.render.string)
  end
end
```

Der Job schreibt in einen Pfad Ihrer Wahl. Wohin die Datei danach geht, etwa in einen Speicher oder eine E-Mail, entscheidet Ihre Anwendung.

## <a id="rack-and-other-frameworks"></a>Rack und andere Frameworks

Jede Rack-Anwendung kann die Bytes direkt zurückgeben:

```ruby
require "docxi"

class ReportApp
  def call(env)
    word = Docxi::Document.new
    word.document.p { |p| p.text "Generated by a Rack app" }

    headers = {
      "content-type" => "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
      "content-disposition" => 'attachment; filename="report.docx"'
    }
    [200, headers, [word.render.string]]
  end
end
```

Binden Sie sie mit `run ReportApp.new` in `config.ru` ein. Derselbe Ansatz funktioniert mit Sinatra, Hanami und jedem Framework, das einen String als Antwortkörper senden kann.

## <a id="scripts-and-command-line-tools"></a>Skripte und Kommandozeilenwerkzeuge

docxi braucht weder Server noch Office-Software, ein einfaches Ruby-Skript genügt also:

```ruby
require "docxi"

word = Docxi::Document.new
word.document.p { |p| p.text "Nightly export" }
File.binwrite(ARGV.fetch(0, "export.docx"), word.render.string)
```
