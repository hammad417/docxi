# 在 Rails、Rack 和后台任务中使用 docxi

docxi 没有插件，也没有内置的集成。它就是返回 `StringIO` 的普通 Ruby 代码，所以任何能发送或保存字符串的地方都能使用它。本页展示常见的接入方式。Rails 控制器的写法与 README 中的示例相同，测试套件会在加载 Rails 5.2 到 8.1 的情况下运行。

## <a id="rails-controller-send-the-file-to-the-browser"></a>Rails 控制器：把文件发送给浏览器

```ruby
class ReportsController < ApplicationController
  def show
    word = Docxi::Document.new
    word.document.p { |p| p.text "Report for #{Date.today}" }

    send_data word.render.string,
              filename: "report.docx",
              type: "application/vnd.openxmlformats-officedocument.wordprocessingml.document"
  end
end
```

`send_data` 会设置 `Content-Disposition: attachment`，因此浏览器会下载该文件。使用 Bundler 时，docxi 会从 Gemfile 自动加载。

## <a id="rails-background-job-build-the-file-outside-the-request"></a>Rails 后台任务：在请求之外生成文件

大型文档，或者依赖慢查询生成的文档，最好放在后台任务中生成：

```ruby
class MonthlyReportJob < ApplicationJob
  queue_as :default

  def perform(path)
    word = Docxi::Document.new
    word.document.p { |p| p.text "Monthly report", bold: true, size: 16 }

    File.binwrite(path, word.render.string)
  end
end
```

该任务把文件写到你指定的路径。文件接下来的去向（例如存储或邮件）由你的应用决定。

## <a id="rack-and-other-frameworks"></a>Rack 和其他框架

任何 Rack 应用都可以直接返回字节内容：

```ruby
require "docxi"

class ReportApp
  def call(env)
    word = Docxi::Document.new
    word.document.p { |p| p.text "Generated by a Rack app" }

    headers = {
      "content-type" => "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
      "content-disposition" => 'attachment; filename="report.docx"'
    }
    [200, headers, [word.render.string]]
  end
end
```

在 `config.ru` 中用 `run ReportApp.new` 挂载它。同样的方法也适用于 Sinatra、Hanami，以及任何能把字符串作为响应体发送的框架。

## <a id="scripts-and-command-line-tools"></a>脚本和命令行工具

docxi 不需要服务器，也不需要办公软件，所以普通的 Ruby 脚本就能使用它：

```ruby
require "docxi"

word = Docxi::Document.new
word.document.p { |p| p.text "Nightly export" }
File.binwrite(ARGV.fetch(0, "export.docx"), word.render.string)
```
